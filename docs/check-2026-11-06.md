# ApiDesk — Audit Checklist 2026-11-06

## 🐛 Bugs

- [ ] **Input fields are visually indistinguishable from disabled/read-only fields** — `bg-[var(--color-muted)]` on inputs matches the surrounding panel background in both light and dark mode. There is no visible border or background contrast to signal editability. Affects URL bar, KeyValueEditor rows, ScenarioViewer step fields, SettingsPanel inputs. Fix: give inputs a distinct background token (lighter in dark, slightly off-white in light) and show a solid border at rest, not just on focus.

- [x] **`scenarios/` directory appeared in the request file tree** — Verified fixed in `workspace_service.go`.

- [x] **`step.assertions` / `step.extractions` / `sr.assertions` / `sr.extracted` can be `null`** — Fixed: `?? []` / `?? {}` guards in ScenarioViewer; additional fix: `r.steps.findIndex` and `result.steps.filter` guarded with `?? []`; `result?.steps[i]` changed to `result?.steps?.[i]`.

- [x] **Scenario tabs not closed when workspace is closed** — Fixed via `scenarioPath` check in `useWorkspace.ts`.

- [x] **Timing bar renders invisible when all segments are 0 ms** — Fixed: empty-state "No timing breakdown available." shown when segments are empty.

- [x] **Retry delay input is visually disabled but reason is not communicated** — Fixed: tooltip added explaining why delay is disabled when retryMaxAttempts is 0.

- [x] **Renaming scenario to an existing name fails silently** — Fixed: `window.alert` on rename error.

- [ ] **Deleting an unsaved (dirty) scenario tab loses changes without warning** — `onDeleteScenario` removes the tab immediately. Should check for dirty state and show a confirmation.

## ⚠️ UI/UX Enhancements

### Scenario view / edit / run screen

- [ ] **Scenario view/edit/run tab style is inconsistent with request editor tabs** — scenario uses pill-style toggle buttons; request editor uses underline-style tabs. Unify to one tab component.

- [ ] **Scenario pane title bar lacks context** — the left pane shows no heading when in View mode. Add a subtle "Steps" / "Results" column header to orient the user.

- [x] **Step result cards show pass/fail by colour only** — Fixed: PASSED/FAILED/SKIPPED text labels shown alongside icons in StepDetailPanel result section.

- [ ] **No loading skeleton for scenario steps during load** — a spinner appears but the pane is blank. Show grey placeholder cards to reduce layout shift.

- [x] **Long step names overflow without truncation** — step names in `StepListRow` already use `truncate`; verified correct.

- [ ] **No visual indication that a scenario has unsaved changes** — the scenario editor has a Save button but no dot / asterisk in the tab title when dirty (unlike request tabs which show an amber dot).

- [x] **Scenario YAML editor Discard has no confirmation when dirty** — Fixed: `handleDiscard` now calls `window.confirm` when `isDirty`.

- [ ] **"Run" button gives no feedback while running** — a spinner appears next to the Run button but the step cards do not show individual in-progress state. Consider adding a pulsing indicator on the currently-executing step.

### Request editor / response viewer

- [ ] **Tab badges (param/header count) are hard to spot** — `text-[10px]` muted text. Use a small solid-background chip with accent colour to make counts visually pop.

- [x] **Timeout input placeholder `0` implies the feature is off** — Fixed: placeholder changed to `"default"` in `RequestEditor.tsx`.

- [ ] **Copy-to-clipboard feedback is easy to miss** — the icon switches to a checkmark for 2.5 s but there is no toast. Add a brief floating "Copied!" toast consistent with other copy actions in the app.

- [ ] **Response body search shortcut is only discoverable on hover** — `title="Search body (Ctrl+F)"` is a hover tooltip only. Add `Ctrl+F` as a small inline label on the button (or at minimum on the find bar trigger area).

- [ ] **No `aria-label` on icon-only buttons** — timing bar button, copy, raw/pretty, search, cancel-send, clear-response, and move-step buttons lack `aria-label`. Screen readers announce nothing meaningful.

- [ ] **Checkboxes have no focus ring** — `accent-[var(--color-accent)]` is set but no `focus-visible:ring` class. Keyboard navigation gives no visual feedback on checkboxes in `KeyValueEditor` and `SettingsPanel`.

### Workspace / sidebar

- [ ] **Inline rename input has no visible affordance** — double-clicking a request or scenario name shows an input, but the input has the same background as the row. Add a visible border or background highlight to make it obviously editable.

- [ ] **Dirty-file dot appears only for requests, not for the active scenario editor** — dirty-tab indicator logic in `WorkspacePanel` checks `dirtyFilePaths`; scenario tabs are never added to this set even when the YAML editor has unsaved changes.

- [ ] **"+ Add row" button in `KeyValueEditor` and "Add Step" button in `ScenarioViewer` have different styles** — `KeyValueEditor` uses plain text link; `ScenarioViewer` uses dashed-border card. Pick one style and apply consistently.

## 🏗 Code / Architecture

- [x] **No shared `inputCls` / `fieldCls` constant** — Fixed: `src/lib/styles.ts` exports `inputCls` and `selectCls` used across all form components.

- [ ] **`buildSegments` is called twice per render in `ResponseViewer`** — once at line ~104 (for rendering) and once at ~126 (for the legend). Wrap in `useMemo`.

- [ ] **`TimingBar` minimum-width normalisation can exceed 100%** — when multiple segments get the 1%-minimum floor, widths are re-normalised, but floating-point rounding may leave the bar 1 px short or over. Add a `Math.round` pass or use a `flex-grow` approach instead of explicit percentages.

## 🔗 CI / CD Integration

- [x] **CLI has no JUnit XML output** — Fixed: `--format junit` added; `reporting.JUnit()` emits standard JUnit XML consumed by Jenkins, GitHub Actions (`dorny/test-reporter`), GitLab CI (`junit` artifact), and CircleCI (`store_test_results`). Exit codes unchanged (0/1/2).

- [x] **No CI integration guide** — Fixed: `docs/ci-integration.md` written covering GitHub Actions, Jenkins (Declarative Pipeline + Freestyle), GitLab CI, CircleCI, Buildkite, secrets injection, multi-scenario loops, and JSON webhook reporting.

- [ ] **CLI has no `--output` flag to write report to a file** — currently only writes to stdout; in CI pipelines users must redirect (`> results.xml`), which fails if the directory doesn't exist. Add `--output <file>` flag that creates parent directories automatically.

- [ ] **CLI `run` command has no `--timeout` flag** — scenario-level timeout can only be set per-step; a global CLI override would allow `apidesk run smoke.yaml --timeout 30s` without editing the YAML.

- [ ] **No `apidesk validate` command** — users cannot check scenario YAML syntax without running it. Add a `validate` command that parses the file and reports schema/assertion errors without executing any HTTP requests.
