# ApiDesk — Audit Checklist 2026-11-06

## 🐛 Bugs

- [ ] **Input fields are visually indistinguishable from disabled/read-only fields** — `bg-[var(--color-muted)]` on inputs matches the surrounding panel background in both light and dark mode. There is no visible border or background contrast to signal editability. Affects URL bar, KeyValueEditor rows, ScenarioViewer step fields, SettingsPanel inputs. Fix: give inputs a distinct background token (lighter in dark, slightly off-white in light) and show a solid border at rest, not just on focus.

- [ ] **`scenarios/` directory appeared in the request file tree** — `buildFileTree` only excluded `environments/`; `scenarios/` was included, allowing a right-click in the tree to open a scenario as a request. Fixed in `workspace_service.go` but worth verifying after `wails build`.

- [ ] **`step.assertions` / `step.extractions` / `sr.assertions` / `sr.extracted` can be `null`** — Go serialises nil slices/maps as JSON `null`; frontend used `.map()` / `Object.entries()` directly. Frontend crashes with `Cannot read properties of null`. Fixed with `?? []` / `?? {}` guards and Go-side empty-slice initialisation, but audit all remaining places where Go arrays flow to frontend `.map()` calls.

- [ ] **Scenario tabs not closed when workspace is closed** — `handleCloseWorkspace` filtered tabs by `filePath` prefix but scenario tabs have `filePath: null`; they persisted after close. Fixed via `scenarioPath` check in `useWorkspace.ts`.

- [ ] **Timing bar renders invisible when all segments are 0 ms** — `buildSegments` clamps each segment to 1% min, but if `durationMs` is 0 all widths are 0 and the bar collapses silently. Needs an empty-state fallback ("No timing data").

- [ ] **Retry delay input is visually disabled but reason is not communicated** — `disabled={(step.retryMaxAttempts ?? 0) === 0}` applies `opacity-40` but no tooltip explains why. User may think it's a bug.

- [ ] **Renaming scenario to an existing name fails silently** — backend `RenameScenario` returns an error string but the UI only logs it; no toast or inline message shown to the user.

- [ ] **Deleting an unsaved (dirty) scenario tab loses changes without warning** — `onDeleteScenario` removes the tab immediately. Should check for dirty state and show a confirmation.

## 🔍 Missing / Expected Features

- [ ] **No "Run from step N"** — scenarios always run from step 1. For debugging a failing step in a long chain the user must re-run everything. Each step in view mode should have a "Run from here" action; backend `RunScenario` needs a `fromStep int` parameter.

- [ ] **No step enable/disable toggle** — there is no way to skip a step without deleting it. Add a checkbox/toggle in the step header (both edit and view mode). The Go domain model and serialiser need an `enabled` bool on `ScenarioStep`.

- [ ] **No step count badge for 0-step scenarios** — `WorkspacePanel` renders the badge only when `s.stepCount > 0`. Show "0" so incomplete scenarios are clearly flagged.

- [ ] **No empty-state guidance when scenario has 0 steps** — view mode shows "No steps defined." but doesn't direct the user. Change to "No steps. Switch to Edit to add your first step."

- [ ] **No confirmation before deleting a scenario** — clicking Delete in the right-click context menu removes the file immediately. Add a confirmation dialog (consistent with the existing Delete Request dialog).

- [ ] **No inline response body in failed step results** — when an assertion fails, the response body is not shown in the `StepResultCard`. The user has to re-run the request manually in the editor to debug. Add a collapsible "Response body" section to `StepResultCard`.

- [ ] **No validation of assertion `path` on save** — a jsonpath or header assertion can be saved with an empty `path`. Add inline validation in `AssertionRow`: require non-empty path when type is `jsonpath` or `header`.

- [ ] **No URL encoding helper in params/headers** — special characters in param values must be manually percent-encoded. Add a per-row button or global toggle for auto-encoding.

- [ ] **No drag-to-resize between scenario definition pane and results pane** — the left pane is fixed at ~42% width. On screens narrower than ~1200 px the right results pane becomes cramped. Implement a draggable divider (same mechanism as the main request/response split).

- [ ] **No keyboard shortcuts to reorder scenario steps** — the move-up / move-down buttons work but require mouse. Add `Shift+Alt+Up / Down` (or similar) in the visual editor.

## ⚠️ UI/UX Enhancements

### Scenario view / edit / run screen

- [ ] **Scenario view/edit/run tab style is inconsistent with request editor tabs** — scenario uses pill-style toggle buttons; request editor uses underline-style tabs. Unify to one tab component.

- [ ] **Scenario pane title bar lacks context** — the left pane shows no heading when in View mode. Add a subtle "Steps" / "Results" column header to orient the user.

- [ ] **Step result cards show pass/fail by colour only** — users with colour blindness cannot distinguish green (pass) from red (fail). Add "PASSED" / "FAILED" / "SKIPPED" text labels alongside the icons.

- [ ] **No loading skeleton for scenario steps during load** — a spinner appears but the pane is blank. Show grey placeholder cards to reduce layout shift.

- [ ] **Long step names overflow without truncation** — step name in both `StepCard` and `StepResultCard` lacks `truncate`. Overflows on small screens or narrow pane widths.

- [ ] **No visual indication that a scenario has unsaved changes** — the scenario editor has a Save button but no dot / asterisk in the tab title when dirty (unlike request tabs which show an amber dot).

- [ ] **Scenario YAML editor has no inline validation** — invalid assertion types or operators produce no warning until Save is attempted. Add a CodeMirror linter or at minimum highlight the Save button in red on parse error.

- [ ] **"Run" button gives no feedback while running** — a spinner appears next to the Run button but the step cards do not show individual in-progress state. Consider adding a pulsing indicator on the currently-executing step.

### Request editor / response viewer

- [ ] **Tab badges (param/header count) are hard to spot** — `text-[10px]` muted text. Use a small solid-background chip with accent colour to make counts visually pop.

- [ ] **Timeout input placeholder `0` implies the feature is off** — tooltip explains "0 uses global default" but the placeholder reads `0` with no hint. Change placeholder to `0 = default` or `default`.

- [ ] **Copy-to-clipboard feedback is easy to miss** — the icon switches to a checkmark for 2.5 s but there is no toast. Add a brief floating "Copied!" toast consistent with other copy actions in the app.

- [ ] **Response body search shortcut is only discoverable on hover** — `title="Search body (Ctrl+F)"` is a hover tooltip only. Add `Ctrl+F` as a small inline label on the button (or at minimum on the find bar trigger area).

- [ ] **No `aria-label` on icon-only buttons** — timing bar button, copy, raw/pretty, search, cancel-send, clear-response, and move-step buttons lack `aria-label`. Screen readers announce nothing meaningful.

- [ ] **Checkboxes have no focus ring** — `accent-[var(--color-accent)]` is set but no `focus-visible:ring` class. Keyboard navigation gives no visual feedback on checkboxes in `KeyValueEditor` and `SettingsPanel`.

### Workspace / sidebar

- [ ] **Inline rename input has no visible affordance** — double-clicking a request or scenario name shows an input, but the input has the same background as the row. Add a visible border or background highlight to make it obviously editable.

- [ ] **Dirty-file dot appears only for requests, not for the active scenario editor** — dirty-tab indicator logic in `WorkspacePanel` checks `dirtyFilePaths`; scenario tabs are never added to this set even when the YAML editor has unsaved changes.

- [ ] **"+ Add row" button in `KeyValueEditor` and "Add Step" button in `ScenarioViewer` have different styles** — `KeyValueEditor` uses plain text link; `ScenarioViewer` uses dashed-border card. Pick one style and apply consistently.

## ♿ Accessibility

- [ ] **No keyboard navigation between scenario definition pane and results pane** — Tab focus does not move between left and right panes; step cards are not focusable. Add `tabIndex={0}` to cards and arrow-key navigation.

- [ ] **Dialog backdrop blur is inconsistent** — `SettingsPanel` and `TimingDialog` both use `bg-black/60` but only one uses `backdrop-blur-sm`. Decide on one style for all modal backdrops.

## 🏗 Code / Architecture

- [ ] **No shared `inputCls` / `fieldCls` constant** — input class strings are duplicated across `RequestEditor`, `KeyValueEditor`, `ScenarioViewer`, `SettingsPanel`. Extract to a `src/lib/styles.ts` constant used everywhere, so the input affordance fix above needs changing in one place.

- [ ] **`buildSegments` is called twice per render in `ResponseViewer`** — once at line ~104 (for rendering) and once at ~126 (for the legend). Wrap in `useMemo`.

- [ ] **`TimingBar` minimum-width normalisation can exceed 100%** — when multiple segments get the 1%-minimum floor, widths are re-normalised, but floating-point rounding may leave the bar 1 px short or over. Add a `Math.round` pass or use a `flex-grow` approach instead of explicit percentages.
