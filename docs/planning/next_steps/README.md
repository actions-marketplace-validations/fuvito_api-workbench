# Next-steps snapshots

Planning documents that capture what the project should do **next** at a point in time — separate from `docs/enhancements/`, which holds design proposals for individual features.

## Naming

`YYYY-MM-DD-next-steps.md` — the date is the day the snapshot was written.

## Lifecycle

Snapshots are point-in-time. Do not edit an old snapshot to keep it current — write a new one with a new date and let the old one stand as the record of what was planned. If an item carries over unchanged, copy it forward with a note on what happened since.

Each snapshot should list items with a **priority order** and enough description that a future snapshot (or contributor) can tell what was done, what was dropped, and why.
