## Verified, no change needed

- **Documentation vs code.** Every flag printed by `--help` for `run`, `conform`, `diff`, `impact`, `validate`, `import`, `generate`, `request`, `coverage list|quality|reset` and `bundle run|validate|import|export` appears in both the user guide and `README-DEVELOPER.md`.
- **Catalog vs CLI.** `TestCatalogMatchesCobra` passes in both directions for `run`, `conform` and `diff`, including the repeatable and deferred flags.
- **Path traversal in `clrsig import`.** Collection, folder and file names go through `SanitizeDirName` / `SanitizeFilename`, which drop dots and slashes, so a hostile collection cannot write outside the output folder; existing files are never overwritten.
- **Spec text in reports.** Paths from a spec are escaped in the new Contracts HTML (the old frontend generator did not escape them) and in the Markdown reports.
- **Builder performance on large folders.** The folder preview re-reads every scenario on each change; measured 330 ms for 1000 scenarios, and builds are debounced with stale results dropped, so no change is needed.
- **Environment expansion at resolve time only.** Parsing and saving an environment keeps `${NAME}` untouched (tested), so saving in the desktop cannot write a real secret to disk.
- **Real-binary runs.** The `${DEMO_BASE}` probe that failed before item 0 passes; an unset variable warns once; the example suite runs with Markdown on screen plus JUnit and HTML files from the same run.

## Known limits and open points

- **Secret redaction is by value and by name.** A secret that is not in an environment variable marked `secret: true` (for example one typed into a scenario file) is not recognised, and a secret value shorter than 4 characters is not replaced inside text. Both are documented in the user guide.
- **`--var` values** are expanded for `${NAME}` like environment values; a literal `${…}` needs `$${…}`.
- **The GitHub Action** exposes none of the newer flags as inputs (`--fail-on`, `--report`, `--var`, `--against`, `--no-recursive`); callers must use the `command`/args route or run the CLI directly. Worth a follow-up if the Action is the main CI path.
- **Report-file collisions** are detected by cleaned path only, so a relative and an absolute path to the same file are not recognised as the same.
- **Line endings:** the working tree mixes CRLF and LF in files edited by different tools; git normalises them, so there is no effect on commits, only noise in local warnings.
